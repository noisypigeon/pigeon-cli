# CLAUDE.md

`pigeon` is a Rust CLI (clap + Mise) that authenticates, syncs, transforms, and optionally encrypts personal email data to local storage or S3-compatible remotes, backed by a unified `keyring` for identities, buckets, and encryption keys. This repo split out of a former personal monorepo (`noisypigeon/noisypigeon`, which still holds this project's terraform infrastructure and blog) via ADR-0084 — that repo's `docs/archived/adr/` holds this repo's own pre-split ADR history too, alongside the terraform/blog ADRs that stayed behind.

## ADRs govern this project

Before making architectural or interface changes, read the ADRs in `docs/adr/` and keep new work consistent with their decisions. If a change would contradict an existing ADR, flag it rather than silently diverging — prefer writing a new ADR (or updating an existing one's Status) over undocumented drift.

- `docs/adr/0001-email-data-sink-transform-cli.md` — the `pigeon email` product interface: authentication, sink, transform, file naming/taxonomy.
- `docs/adr/0002-pigeon-cli-scaffold.md` — CLI scaffold and tooling: package/binary naming, clap argument structure, command dispatch, stub/exit-code conventions, testing approach.
- `docs/adr/0003-imap-connectivity-and-authentication.md` — IMAP crate choice, per-provider authentication (app/bridge passwords, not OAuth2), credential lifetime, local credential storage, and multi-provider selection.
- `docs/adr/0004-mise-run-task-for-cli.md` — the `mise run pigeon` task for running the built binary.
- `docs/adr/0005-email-sink.md` — `pigeon email sink`: identity selection, connecting, read-only enforcement (`EXAMINE`/`BODY.PEEK[]`), `.eml`-per-message output layout, resume mechanics, progress reporting.
- `docs/adr/0006-email-transform.md` — `pigeon email transform`: EML parsing/HTML-to-Markdown crates, ADR-0001 naming-scheme reuse, flat folder structure, taxonomy cross-cuts via namespaced frontmatter tags, attachment organization.
- `docs/adr/0007-email-sync.md` — merges `sink`+`transform` into `pigeon email sync`: per-UID fetch/transform/verify/delete pipeline, `.processed` resume marker, `source:`→`uid:` frontmatter amendment, `--debug sink`/`--debug transform` for phase-level (non-destructive) access. Reverses ADR-0001's permanent-raw-archive default.
- `docs/adr/0008-src-module-layout.md` — groups all email-specific code under `src/email/` (cli/commands/logic together), keeping top-level `src/cli.rs`/`src/commands/mod.rs` as thin roll-ups, so future command groups get their own sibling folder.
- `docs/adr/0009-remote-storage.md` — `pigeon remote`: rclone-style S3-compatible storage via the `minio` crate, bucket-scoped remotes (`name:path` addressing), `configure`/`list-buckets`/`ls`/`lsd`/`copy`, secret key in the OS keychain per ADR-0003's precedent, `src/remote/` reusing ADR-0008's module shape.
- `docs/adr/0010-remote-storage-improvements.md` — amends ADR-0009 from first real use: `name`→`alias` rename, reordered/simplified `configure` prompts, drops the dead `region` field and the unreliable inline list-buckets step (replaced by a `bucket_exists` verify-before-save check), concise S3 error formatting, and new `list`/`edit`/`remove` commands for configured remotes.
- `docs/adr/0011-email-sync-remote-upload.md` — wires `--output-remote` into `pigeon email sync`: per-message upload inline in the existing verify/resume pipeline, `remote::client::upload_if_changed`'s ETag/MD5-based same-file-or-different-file check (warn-then-proceed on a real collision), default-flow-only (`--debug` modes reject it) — `email`'s first justified dependency on `remote`.
- `docs/adr/0012-email-output-deduplication.md` — deduplicates byte-identical content in `--output-dir`: content-hashed (MD5) attachment reuse (no schema change) and whole-message merge-into-canonical-file via a new additive `also-in:` frontmatter field, both keyed off two new per-identity `.attachment-hashes`/`.message-hashes` files in `--staging-dir`, composing with ADR-0011's upload dedup for free.
- `docs/adr/0013-sync-progress-and-attachment-name-sanitization.md` — per-mailbox transform-phase progress bar, plus sanitizes sender-controlled MIME attachment names to prevent path-separator crashes.
- `docs/adr/0014-concurrent-mailbox-processing.md` — `--concurrency` flag, one `ImapSession` per worker, dedup indexes behind `Arc<Mutex<ContentIndex>>`, `MultiProgress`.
- `docs/adr/0015-stable-concurrent-progress-bars.md` — routes all prints through `MultiProgress::println`/`suspend` so concurrent progress bars never get corrupted by a stray `println!`.
- `docs/adr/0016-keychain-stability-and-cli-cleanup.md` — macOS ad-hoc codesign fix for keychain ACL persistence across rebuilds, plus CLI cleanup (`list-identities`→`list`, `--staging-dir`/`--output-dir`→`--local-output`, `--output-remote`→`--remote-output`).
- `docs/adr/0017-rename-remote-to-dataops.md` — renames `src/remote`/`pigeon remote` to `src/dataops`/`pigeon dataops`: `configure`/`edit`/`remove` move under a new `bucket-config` subgroup (`new`/`edit`/`remove`), `list-buckets` is removed, `list`/`ls`/`lsd`/`copy` are removed as CLI commands but kept as reusable internal functions, and every internal `Remote`-rooted identifier (including the on-disk `bucket-configs.toml` filename and the OS-keychain service name) renames to `BucketConfig`/`bucket-config` terminology — all breaking, no migration shim.
- `docs/adr/0018-crates-io-publishing.md` — publishes `pigeon-cli` to crates.io (GPL-3.0-or-later), manual `mise`-driven publish.
- `docs/adr/0019-local-first-sync-and-upload-checkpoints.md` — splits `email sync` into fetch → transform+dedup → upload phases, upload running only after all local work is done, with a new `.uploaded` checkpoint; removes ADR-0012's inline reupload-after-merge mechanism.
- `docs/adr/0020-generic-transform-dedup-in-dataops.md` — genericizes `ContentIndex`, `amend_frontmatter_for_duplicate`, `unique_path`, `sanitize_filename`, `yaml_quote`, `collect_files` for reuse beyond email.
- `docs/adr/0021-job-orchestration-wizard.md` — `pigeon job run email-sync` replaces `pigeon email sync`: wizard-resolved identities/local-output/remote-output/concurrency, batch-level concurrency spanning every identity's mailboxes, UID-keyed staging tree, dedup as its own sequential post-transform pass. **§8's narrow `--yes` semantics superseded by ADR-0114.**
- `docs/adr/0022-unified-keyring-command.md` — unifies `pigeon email authenticate`/`pigeon dataops bucket-config` into `pigeon keyring add/modify/delete/list`, one `keyring.toml`, one OS-keychain service, globally unique aliases across kinds.
- `docs/adr/0023-lib-commands-trait-restructure.md` — restructures into trait-based `src/core/` (`Job`, `Transform`, `Dedup`, `KeyringEntry`, `WizardInput`) with concrete implementations in `src/commands/`.
- `docs/adr/0024-concurrent-upload-phase.md` — upload becomes one concurrent, cross-identity phase (`stream::buffer_unordered`) with its own progress bar and per-file retry-with-backoff, instead of sequential per-identity.
- `docs/adr/0025-encrypt-before-upload.md` — `email-sync` uploads can be encrypted client-side with AES-256-GCM-SIV and a content-derived deterministic nonce, so identical plaintext still dedups correctly against S3 ETags even when encrypted.
- `docs/adr/0026-encryption-keys-in-keyring.md` — `pigeon keyring add/modify encryption-key` manages symmetric encryption keys (generated or imported) in the OS keychain.
- `docs/adr/0027-encryption-is-a-per-run-choice.md` — an encryption key can default to a bucket-config (chosen by alias) but is always overridable per run via `--encryption-key` or interactively; non-interactive runs fall back to the bucket's default instead of always skipping encryption.
- `docs/adr/0028-decrypt-files-job.md` — `pigeon job run decrypt-files` decrypts `*.enc` files from a local input directory into an output directory using a configured encryption key.
- `docs/adr/0029-dev-cycle-pipeline.md` — every substantive change lands via branch → PR → local `mise run ci` gate → auto-merge → a `CHANGELOG.md [Unreleased]` entry; see "Dev cycle" below.
- `docs/adr/0030-fix-attachment-loss-in-dedup.md` — root-causes silent, total attachment loss in `run_dedup_pass`: a staged attachment's `staged_relpath` is final-location-relative, not staging-root-relative like `md_staged_relpath`, so `staging_dir.join(staged_relpath)` never finds the real file and the idempotency guard silently skips it. Fix: reconstruct the real staged path from `md_staged_relpath`'s parent + `uid`, no checkpoint format change, self-healing on re-run.
- `docs/adr/0031-out-of-scope-issue-tracking.md` — genuinely-deferred `## Out of scope` bullets get filed as GitHub issues, labeled `out-of-scope` plus an `area:*` category, and linked back into the ADR line via `mise run adr-issue`; recurring gaps reuse one issue across ADRs.
- `docs/adr/0032-manifest-progress-and-attachment-count.md` — `job run email-sync`'s manifest-gathering phase (per-identity IMAP connect/list/search, previously silent) gets a `MultiProgress` connect line plus a per-identity mailbox-scoped progress bar; the wizard's pre-run summary table gains an `ATTACHMENTS` column, an estimate computed from each pending message's IMAP `BODYSTRUCTURE` (no body content transferred), persisted as a 4th `.manifest` column that self-heals on a pre-upgrade file.
- `docs/adr/0033-dedup-observability-and-hardening.md` — gives `run_dedup_pass` a progress bar and fixes its (and `transform.rs`'s) `eprintln!`/`MultiProgress::suspend` gap; replaces the flat `failed` counter with a per-category `FailureBreakdown` and gives `verify_transformed` a reason enum; narrows the manifest `ATTACHMENTS` estimate's heuristic and prints it next to a real per-run staged count; bounds progress-bar prefix width to 24 chars; strengthens `yaml_quote` to escape control characters (sender display name/subject frontmatter injection).
- `docs/adr/0034-fix-stale-manifest-attachment-estimate.md` — root-causes the manifest `ATTACHMENTS` estimate being stuck at zero for every identity: `gather_pending`'s persisted-`.manifest` reuse fast-path (`all_known`/`persisted_sizes`) caches a UID's attachment count indefinitely once written, bypassing `count_attachments` entirely and never invalidating on a heuristic upgrade or even a `UIDVALIDITY` reset. Fix: remove the reuse fast-path, always call `pull_manifest` fresh (no body content transferred either way).
- `docs/adr/0035-pretrust-keychain-access.md` — **Rejected.** Root-caused `job run email-sync` prompting for the macOS keychain password 5-10 times per run (one distinct `keyring::Entry` per identity/bucket-config/encryption-key alias, each needing its own OS-level access grant), but its proposed fix (shell out to `security add-generic-password -T <current-binary-path>` instead of the `keyring` crate) was disproved by a live implementation attempt: routing reads through `/usr/bin/security` makes *that* process the one needing Keychain trust, not `pigeon`, so `-T <pigeon-path>` didn't suppress repeat prompts. No code landed; problem still open.

Amends ADR-0018. Reversed by ADR-0086, which moved the manifest back to repo root and collapsed the changelog/README back to one each.
- `docs/adr/0051-github-repo-rename-reference-updates.md` — updates every in-repo GitHub link and the local `origin` remote for the GitHub repo rename `pigeon-cli` → `pigeon` (crate/package name and `pigeon` binary name are unaffected, unrelated decisions); bumps the crate to `0.2.1` for the corrected `Cargo.toml` `repository` field ahead of a manual `cargo publish`. Amends ADR-0018. (The repo has since moved again, to `noisypigeon/pigeon-cli`, via ADR-0084's split.)
- `docs/adr/0065-bisect-unparseable-bodystructure.md` — root-causes a `job run email-sync` crash to `imap-proto` 0.16.7 only recognizing `MESSAGE`/`RFC822` in `BODYSTRUCTURE` (any other `MESSAGE` subtype, e.g. a bounce's `DELIVERY-STATUS` or an internationalized `GLOBAL` part, fails the entire batched `UID FETCH`); fixes `pull_manifest` to bisect a failing UID batch and isolate the poisoned UID(s) with a zeroed placeholder, instead of losing the whole mailbox's manifest data.
- `docs/adr/0068-best-effort-imap-logout.md` — fixes three IMAP `LOGOUT` calls (`email_sync/mod.rs`'s `gather_pending`, `email_sync/sink.rs`'s debug-sink path, `keyring/email/imap_client.rs`'s `verify_login`) that propagated a logout failure as fatal even though the real work already succeeded — in `gather_pending`'s case, discarding the whole identity's already-gathered manifest data too. Matches the best-effort `let _ = ...logout().await;` pattern `email_sync/worker.rs` already used.
- `docs/adr/0071-imap-connection-storm-and-fetch-resilience.md` — fixes a `job run email-sync` connection storm at high `--concurrency` against multiple identities ("Too many simultaneous connections") with a new per-identity connection cap (`--max-connections-per-identity`, default 6), retries a transiently-failed batch once before giving up, and collapses per-UID "missing file" warning spam into one line per batch.
- `docs/adr/0073-cross-cutting-observability.md` — a durable JSONL observability log (`pigeon.jsonl`) for every `job run`, `--log-level`/`--log-file` flags, a `command`-named tracing span wrapping each dispatch (`run_instrumented`), and a periodic `ResourceSampler` capturing RSS/CPU during a run.
- `docs/adr/0074-pull-transform-job.md` — adds `pigeon job run pull-transform`: pulls a bucket, expands zips, recodes media via `ffmpeg` with verify/fallback, dates and dedups by content, and organizes/uploads the result.
- `docs/adr/0075-pull-transform-progress-visibility.md` — gives `pull-transform` a live progress bar plus named call-outs for large downloads/recodes, so a long run no longer looks hung.
- `docs/adr/0076-harden-pull-transform-memory.md` — streams `pull-transform` downloads and zip expansion straight to disk instead of buffering whole objects/zip contents in memory, root-causing and fixing a real SIGKILL crash against 50-100GB zip archives; adds a live disk-space preflight check.
- `docs/adr/0077-pull-transform-file-type-selection.md` — adds `--file-types`, `--expand-zips`, and `--image-format`/`--video-format`/`--audio-format` to `pull-transform`, letting a run filter which extensions get pulled/transformed/uploaded, opt individual zips out of expansion (upload as-is instead), and adapt the media-transcoding mapping from a small vetted per-category menu.
- `docs/adr/0078-job-run-log-analysis-procedure.md` — formalizes a repeatable procedure for analyzing `pigeon.jsonl` job-run logs (isolating a run, reading the resource-sample stream, cross-checking failure tallies) and packages it as the `.claude/skills/analyze-job-run` skill — no source changes.
- `docs/adr/0080-per-identity-imap-connection-cap-and-transform-warning-logging.md` — adds an optional per-identity IMAP connection cap on `Identity` (set via `pigeon keyring add/modify email`), overriding `job run email-sync`'s job-wide `--max-connections-per-identity` default for that identity only; routes `transform.rs`'s four lenient-skip warnings through `tracing::warn!` instead of `eprintln!`, so they now reach the JSONL observability log.
- `docs/adr/0081-email-pull-job.md` — adds `pigeon job run email-pull`, a sibling to `email-sync` that pulls raw `.eml` files and unpacked attachments (no Markdown/frontmatter transform), deduplicates attachments only (not whole messages, sidestepping `email-sync`'s frontmatter-rewrite dedup mechanism that raw `.eml` has no equivalent for — the same problem ADR-0074's `pull_transform::dedup` already solved the same way), never offers encryption, and optionally uploads unencrypted to a bucket-config; reuses `email_sync::sink`/`manifest`'s pure IMAP mechanics and the ADR-0074 shared upload/wizard infrastructure directly, with its own adapted worker-loop/checkpoint module per this codebase's duplicate-until-the-third-consumer precedent.
- `docs/adr/0082-dedupe-job.md` — adds `pigeon job run dedupe`: recursively scans a source bucket, always inflates every zip encountered (zip containers themselves are never uploaded, only their inflated contents), content-hashes (SHA-256) every file bucket-wide to keep one byte-identical copy of each, writes a human-readable merge report, and optionally uploads the result unencrypted to a different bucket-config; hoists `pull-transform`'s ADR-0076 disk-space-preflight/streaming-download helpers into a new shared `commands/job/download.rs` (mirroring `upload.rs`'s own ADR-0074 hoist) and reuses `pull_transform::archive`'s zip-expansion directly, with its own adapted bucket-listing/checkpoint/placement modules for the rest. **Renamed `dedupe` → `deduplicate` by ADR-0096.**
- `docs/adr/0083-sort-job.md` — adds `pigeon job run sort`: takes a mandatory input and output bucket, downloads the input bucket, flattens it into top-level `<extension>/` folders by each file's literal as-found extension (no canonicalization), and uploads to the output bucket, never encrypting; designed to run after `dedupe` (ADR-0082) so a filename collision is always disambiguated via `unique_path` rather than hash-checked, with no `ContentIndex`/`Dedup`/zip-expansion machinery at all; reuses `commands/job/download.rs` (ADR-0082 §0) as its third real consumer, and defers (via a filed `adr-issue`, not silently) generalizing the by-now-three-times-duplicated bucket-listing/checkpoint pattern given the on-disk migration risk to already-shipped jobs. **Reversed by ADR-0094**, which removed the job entirely once it was found redundant with `dedupe`'s own placement step.
- `docs/adr/0084-split-pigeon-cli-repo.md` — splits `service/pigeon-cli` out of the former `noisypigeon/noisypigeon` monorepo into this repo, via a full-history force-push followed by one ordinary prune commit in each repo (not a `git filter-repo` rewrite) — a partial reversal of ADR-0036's "future monorepo" framing and the consolidation `noisypigeon/noisypigeon`'s own ADR-0037/0052 did, stated explicitly rather than silently diverging. - `docs/adr/0085-linux-keyring-support.md` — fixes `pigeon keyring add`/`modify`/`delete`/`list` failing on headless Linux ("No default store has been set") by switching Linux to the kernel-keyutils `keyring` backend (`linux-keyutils-keyring-store`, no daemon/D-Bus needed) instead of the default D-Bus Secret Service backend; accepted trade-off: Linux secrets don't survive a reboot, confirmed acceptable for ad-hoc/interactive (non-cron) use.
- `docs/adr/0086-move-crate-to-repo-root.md` — moves the crate from `service/pigeon-cli/` to repo root now that ADR-0084 left this repo holding nothing else; collapses the two `CHANGELOG.md`s/`README.md`s/`.gitignore`s into one each, drops the `--manifest-path` ceremony from every `.mise.toml` task, rewrites 40 ADRs' + this file's historical `service/pigeon-cli/...` path citations to match (preserving genuine historical-fact mentions, e.g. ADR-0084's own), and adds an explicit `include` list to `Cargo.toml` so `cargo publish` doesn't regress ADR-0050's packaging-scope fix now that the manifest is back at a root that also holds `docs/adr/`/`CLAUDE.md`/`.claude/`. Amends ADR-0018, ADR-0029, and ADR-0050.
- `docs/adr/0089-dedupe-upload-only-and-streaming-uploads.md` — adds `job run dedupe --upload-only` to resume uploading an already-completed local run (skipping download/hash/placement and the source bucket credentials they'd need) after a real OOM kill left one 560k-file run stuck mid-upload with no way to resume; roots that OOM to `upload_one`'s whole-file `fs::read`-then-clone-per-retry plus `run_dedupe_job` keeping its full `ContentIndex`/merge-report/`placed_keys` state alive through the entire upload phase, and fixes both — `upload_if_changed` now takes a `UploadBody::Path`/`Bytes` enum and streams a plaintext upload straight from disk via `minio`'s `put_object_content` (multipart above 64MiB, removing the prior 5GB single-PUT cap everywhere that shares `upload.rs`, not just `dedupe`), while `run_dedupe_job` drops its dedup-pass state in a scoped block before upload runs.
- `docs/adr/0090-generalize-dedupe-fixes-to-other-jobs.md` — generalizes ADR-0088/0089's dedupe-only fixes to the rest of the job types, per a per-job audit (not uniformly): `pull-transform` and `decrypt-files` get the CPU-aware `CpuConcurrencyInput` default (now hoisted into `shared_wizard.rs`, dedupe included) and `spawn_blocking`-wrapped CPU-bound calls (zip expansion, hashing, EXIF parsing, AES decryption); `pull-transform` and `sort` get their in-memory dedup/placement state scoped to drop before the upload phase; `pull-transform`, `sort`, `email-sync`, and `email-pull` all gain `--upload-only` (the email jobs' version is per-identity, since their local trees are per-identity, skipping an incomplete identity with a warning rather than failing the whole command); `sort`/`email-sync`/`email-pull`'s concurrency defaults are deliberately left untouched (no CPU-bound work, or IMAP-I/O-bound respectively). Flags a real pre-existing bug found along the way (`pull-transform`'s upload walk sweeping up its own `.processed`/`.content-hashes`/`.uploaded` bookkeeping files, since it never adopted dedupe/sort's separate `result/` subdirectory split) without fixing it, filed as [noisypigeon/pigeon-cli#7](https://github.com/noisypigeon/pigeon-cli/issues/7).
- `docs/adr/0091-upload-phase-performance-fixes.md` — fixes three upload-phase problems found by analyzing a real `job run dedupe` run's logs: `upload_if_changed` (`client.rs`) skips its pre-upload local hash entirely when the destination key doesn't exist yet (previously computed unconditionally, doubling disk reads for a fresh-destination run); `upload_one` (`upload.rs`) gains a size-scaled per-attempt timeout (a 60s floor plus a 10 MiB/s-floor-throughput allowance) so a stalled upload can't hold a concurrency slot indefinitely (three real uploads each hung exactly 1800s with no timeout at all); and a new `--upload-concurrency` flag (`UploadConcurrencyInput`, default 16) decouples upload-phase parallelism from each job's unrelated `--concurrency` (CPU-bound hash/transform work, or IMAP fetch), generalized to all 5 upload-capable jobs (`dedupe`, `sort`, `pull-transform`, `email-sync`, `email-pull`) per ADR-0090's audit-and-generalize precedent — including each job's `--upload-only` path, where `--upload-concurrency` now fully replaces `--concurrency`'s effect. Defers a separately-decided question (53 unopenable nested zips silently dropped during the same run) to its own ADR.
- `docs/adr/0094-remove-sort-job.md` — removes `pigeon job run sort` (ADR-0083) entirely: `dedupe` (ADR-0082) already performs the same extension-flattening as a side effect of its own placement step, and in practice every bucket handed to `sort` had already been through `dedupe` first, so `sort`'s one distinguishing capability (flattening a bucket known-unique but not yet organized, without re-paying for a content-hash pass) was never actually exercised — a second job type, CLI surface, and test suite duplicating logic `dedupe` already produces, carrying a foot-gun ADR-0083 itself had flagged (nothing enforces `sort`'s source was actually deduped first). `pigeon` goes from 5 upload-capable job types to 4.
- `docs/adr/0095-prefer-dated-duplicate-keys.md` — fixes `dedupe`'s `place_and_report` (`src/commands/job/dedupe/dedup.rs`) always keeping whichever duplicate's `original_key` sorts lexicographically first, found from a real run where the source bucket's `0000-00-00-*` "unknown date" sentinel sorted ahead of real dated keys and 797 of 855 duplicates kept the undated copy; adds an `is_undated_key` check so a dated key now wins over an undated one, falling back to the prior lexicographic order as a tie-break. Does not remediate already-written buckets (upload never deletes).
- `docs/adr/0096-rename-dedupe-and-add-reduce-job.md` — renames `pigeon job run dedupe` → `pigeon job run deduplicate` (mechanical, no behavior change), and adds `pigeon job run reduce`: runs after `deduplicate`, classifies each top-level `<extension>/` directory of its already-deduplicated source bucket as either genuinely valuable or an artifact/piece of media (TV, movie, software installer, disk image) easily reproduced from an external canonical source via a curated, hardcoded extension table (overridable per run with repeatable `--force-valuable`/`--force-reproducible` flags), and forwards only the valuable extensions to a mandatory destination bucket — reproducible extensions are never even downloaded, avoiding the download-then-reupload round-trip every other bucket-to-bucket job pays, since this codebase has no server-side bucket-to-bucket copy primitive. Hoists `extension_of` (into `core::data`) and `SourceBucketInput` (into `shared_wizard.rs`) on `reduce`'s third-consumer trigger, per the "duplicate until the third consumer" precedent ADR-0082 itself deferred. **The `reduce`-adding half is reversed by ADR-0103**, which removed the job entirely; the `dedupe` → `deduplicate` rename is unaffected.
- `docs/adr/0097-job-lifecycle-logging-and-metric-labels.md` — adds a `"command started"` log line bracketing the existing `"command finished"` one (`run_instrumented`), and hoists every job wizard's duplicated, unlogged `fail()` into one shared `commands::fail` that also emits a `tracing::error!("job failed")` with the real reason before translating an `Err` into an exit code (closes [#18](https://github.com/noisypigeon/pigeon-cli/issues/18)); adds an `instance` label (via a new cached `observability::instance()`) to every custom metric, and `source_bucket`/`destination_bucket` labels (the pigeon-configured alias) to `pigeon_job_phase_total` and the five `pigeon_upload_*` metrics wherever a `BucketConfig` is already in scope.
- `docs/adr/0098-fix-zip-expansion-data-loss-and-false-failures.md` — root-causes two real `job run deduplicate` runs' silent data loss and false failures in the `pull_transform::archive`/`deduplicate::worker` zip-expansion path (shared by `deduplicate` and `pull-transform`): replaces the single run-wide 500 GiB extraction cap (`MAX_TOTAL_EXTRACTED_BYTES`) with a per-archive compression-ratio guard so one large legitimate bucket stops silently dropping every later zip member once the old global cap was hit; counts dropped members as real, exit-code-affecting failures instead of only `tracing::warn!`ing them; taints and excludes a zip's root key from `.processed` checkpointing whenever any descendant fails or is dropped, so a rerun actually retries it (previously checkpointed unconditionally on successful expansion, regardless of what happened inside); skips macOS AppleDouble/`__MACOSX` entries before treating anything ending in `.zip` as a nested zip, removing a class of false `"Could not find EOCD"` archive failures; propagates the `command` tracing span into the `tokio::spawn`/`spawn_blocking` work that previously ran outside it (fixing the `analyze-job-run` skill's documented log filter); and fixes `upload.rs`'s `identity` span field and every non-`--upload-only` `upload_result` call site to carry the destination bucket's alias instead of the source's (ADR-0097 fixed the equivalent metric label but not this span field). Resolves the item ADR-0091 deferred to "being decided and written up separately." Explicitly declines to change empty-file content-hash collapsing, reaffirming ADR-0082's byte-identical-not-semantic design.
- `docs/adr/0099-fix-zip-member-key-corruption-and-observability.md` — from a clean `job run deduplicate` run's own analysis: fixes a zip member's synthetic `outer.zip!member` key leaking into its placed filename/extension (an extensionless member corrupted both) by stripping everything up to the last `!` before any `Path`-based name/extension derivation, shared by `deduplicate` and `pull_transform`; adds four `tracing::info!` phase-boundary log lines bracketing `deduplicate`'s and `pull_transform`'s local download/expand/hash/placement/upload phases (previously completely silent in `pigeon.jsonl`) and demotes `upload_one`'s per-file tracing span to `level = "debug"`, cutting one real run's log volume from 143k lines to a handful by default across all five upload-capable jobs; replaces the permanent per-large-download `MultiProgress::println` announcement with a transient progress-bar message (`download::DownloadAnnounce`) shared by `deduplicate`/`pull_transform`/`reduce`; extends zip-expansion's existing AppleDouble/`__MACOSX` skip to also drop `.DS_Store`, `.git`, and `node_modules` entries as unconditional tooling noise; and adds a `kept_original_key` column to `deduplicate-report.txt` by extending `ContentIndex`'s on-disk format to a backward-compatible 3-field tab-separated line. Explicitly declines to canonicalize whitespace-containing literal extensions (an existing ADR-0083 precedent) or to change the upload timeout scheme (every observed timeout already recovered via the existing retry).
- `docs/adr/0100-job-report-log-transcript-upload.md` — adds a mandatory `--report-bucket` wizard step (`ReportBucketInput`, `shared_wizard.rs`) to all 6 job types, uploading that run's report, the shared `pigeon.jsonl` log (uploaded whole, not filtered to this run), and a transcript of its wizard-level printed narration to the configured bucket under a `{date}-{job-name}-{run-id}/` prefix, always unencrypted and best-effort (a failed upload never changes the job's own exit code); `deduplicate` keeps its existing bespoke report, the other 5 job types gain a generic `Debug`-formatted one; `decrypt-files` gains its first-ever bucket-config dependency. The transcript deliberately captures only each wizard's own narration lines, not the per-item `MultiProgress` status lines deep in each job's `worker.rs` -- wrapping every `MultiProgress` construction site turned out to be a much larger, riskier refactor than planned (over a dozen independent construction sites across `worker.rs`/`dedup.rs`/`upload.rs`/`sink.rs` per job, plus test call sites), so the scope was deliberately narrowed instead.
- `docs/adr/0101-rclone-import-job.md` — adds `pigeon job run import`, a 7th job type that shells out to a single `rclone copy <source> <destination>` invocation with a fixed set of performance/retry flags (not configurable per run); `--source`/`--destination` are raw rclone `remote:path` strings passed straight through, never pigeon `BucketConfig`/keyring aliases -- the backing `rclone.conf` is provisioned by an external, terraform-driven deployment process outside this crate's scope, which is also the point of wrapping rclone rather than pigeon's own S3-only jobs. Redirects rclone's own logging to `--use-json-log` at a pigeon-managed per-run path instead of a fixed plain-text file, parses it after the subprocess exits into `tracing::info!`/`warn!` phase-boundary and per-object-failure events plus a `pigeon_job_phase_total` metric (both ADR-0073/0097 conventions), and passes that same JSON log file directly as this job's ADR-0100 report artifact rather than writing a second, separate summary. Conforms to ADR-0100's `--report-bucket` step from day one.
- `docs/adr/0102-import-job-live-metrics-parity.md` — closes a metrics-parity gap found auditing `import` against the other 6 job types: `pigeon_job_macro_phase` and `pigeon_upload_bytes_total`/`pigeon_upload_outcomes_total` never appeared for `pigeon_job="import"` at all, and its one `pigeon_job_phase_total` call fired only once, after the whole `rclone copy` subprocess had already exited. Replaces the one-shot `rclone_log::parse_and_report` with an incrementally-pollable `RcloneLogTailer` (tracks a byte offset and a buffered partial line, returns a delta since the last poll so repeated polling never double-counts) and switches `worker.rs` from `Command::output()` to `spawn()` plus a concurrent `tokio::select!` poll loop (10s ticks, independent of rclone's own `--stats 30s`) racing the child's exit, so metrics update live through a long-running transfer instead of only at the end; calls `set_macro_phase("import", true)` once at spawn (import has no separate local-work phase to flip from `false`, unlike every other job); reuses `observability::metrics::NO_BUCKET` (now `pub(crate)`) for the new metrics' `destination_bucket` label rather than a raw, unbounded-cardinality rclone connection string. Deliberately leaves `pigeon_upload_attempts_total`/`pigeon_upload_duration_seconds` unimplemented for import (genuinely per-file measurements rclone doesn't expose without `-v`-level logging this job doesn't enable) and files that gap as an `out-of-scope` issue per ADR-0031 rather than faking them from aggregate counts.
- `docs/adr/0103-remove-reduce-job.md` — removes `pigeon job run reduce` (ADR-0096) entirely: its automatic valuable/reproducible extension-table filter has been replaced by running `import` then `deduplicate` as two separate, manually-verified steps, with the keep/discard judgment now done by hand instead of via a hardcoded extension table. Deletes `src/commands/job/reduce/` wholesale (same one-directional-dependency shape confirmed for ADR-0094's `sort` removal, which this ADR mirrors); `core::data::extension_of`/`shared_wizard::SourceBucketInput` stay put since both retain 2 consumers (`deduplicate`, `pull_transform`) after the removal, unlike `sort`'s removal which did un-hoist `ConcurrencyInput`. `pigeon` goes from 7 job types to 6, upload-capable jobs from 5 to 4.
- `docs/adr/0114-non-interactive-flag.md` — renames `--yes` to `--non-interactive` on all 8 job CLI variants and widens its effect: `WizardInput::resolve()` (`src/core/wizard.rs`) gains a `non_interactive: bool` parameter, and when set, every wizard input (not only the final "proceed?" confirmation) resolves via its `non_interactive_fallback()` regardless of whether stdin is actually a TTY. Reverses ADR-0021 §8's narrow `--yes` semantics; fixes a real hang where an interactive-shell run with `--yes` and one omitted optional flag (e.g. `transform`'s `--tpslimit`) still blocked on an interactive prompt.

## Dev cycle: how work lands (ADR-0029)

Single-contributor repo, but every substantive change goes through a real PR. When asked to write an ADR, or to implement one already written, follow this without pausing for confirmation at each step — these steps *are* the standing authorization, per ADR-0029:

1. **Branch.** Once the ADR's content (or the implementation plan) is approved, `git checkout main && git pull && git checkout -b adr-XXXX-<slug>`. Reuse one branch for both writing the ADR and implementing it when a single request covers both. One branch in flight at a time.
2. **Build.** Commit the ADR file and/or implementation on that branch, using this repo's existing commit convention (`type(adr-XXXX): summary`).
3. **Gate.** `mise run ci` must be clean before opening a PR.
4. **PR.** `gh pr create` — title matches the commit convention; body is a condensed ADR (short Context, condensed Decision bullets, a relative link to the full ADR file), never the full text.
5. **Changelog.** Once the PR exists, append one bullet in the same follow-up commit to `CHANGELOG.md`'s `[Unreleased]` section (top of file; create it if missing): `- ADR-XXXX: <one-line description> ([#N](PR URL))`.
6. **Merge.** `gh pr merge --squash --delete-branch` once CI is clean — no further confirmation needed.

Releases stay manual: cutting one means hand-retitling `[Unreleased]` to `[x.y.z] - date` and starting a fresh empty `[Unreleased]` section — not part of this pipeline.

When an ADR's `## Out of scope` section has a genuinely-deferred item (not a permanent design boundary), file it via `mise run adr-issue` while landing that ADR — reuse an existing `out-of-scope`-labeled issue with `--issue N` if the same gap was already raised elsewhere. See ADR-0031.

## Commands

- `mise run build` — build the `pigeon` binary.
- `mise run pigeon -- <args>` — run the `pigeon` binary, e.g. `mise run pigeon -- email list`.
- `mise run test` — run the test suite.
- `mise run fmt` / `mise run fmt-check` — format / check formatting.
- `mise run lint` — clippy, warnings denied.
- `mise run ci` — fmt-check + lint + test, the full local gate.
- `mise run adr-issue -- <args>` — file (or reuse) a GitHub issue for an ADR's Out of scope bullet and link it back into the ADR; see ADR-0031.
