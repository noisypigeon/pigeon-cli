# CLAUDE.md

`pigeon` is a Rust CLI (clap + Mise) that authenticates, imports, transcodes, and deduplicates personal data into S3-compatible remotes, backed by a unified `keyring` for identities and buckets. This project's Terraform infrastructure lives in [`noisypigeon/runway`](https://github.com/noisypigeon/runway): its `scaleway/{iam-application,cockpit-observability,iam-api-key,iam-policy,object-bucket,pigeon-cluster}` leaves named `pigeon-cli*`, and `grafana/dashboard/pigeon-cli`. The blog is in [`noisypigeon/blog`](https://github.com/noisypigeon/blog). The family's infrastructure ADRs are `LIB-` records in [`noisypigeon/library`](https://github.com/noisypigeon/library)'s `docs/adr/`, which also holds the closed `DEV-` corpus under `archive/`. The spokes keep none of their own (LIB-0017); this repo's `docs/adr/` is the exception.

## ADRs govern this project

Before making architectural or interface changes, read the ADRs in `adr/` (`CLI-NNNN-<slug>.md`) and keep new work consistent with their decisions. If a change would contradict an existing ADR, flag it rather than silently diverging — prefer writing a new ADR (or updating an existing one's Status) over undocumented drift.

- `adr/CLI-0095-prefer-dated-duplicate-keys.md` — fixes `dedupe`'s `place_and_report` (`src/commands/job/dedupe/dedup.rs`) always keeping whichever duplicate's `original_key` sorts lexicographically first, found from a real run where the source bucket's `0000-00-00-*` "unknown date" sentinel sorted ahead of real dated keys and 797 of 855 duplicates kept the undated copy; adds an `is_undated_key` check so a dated key now wins over an undated one, falling back to the prior lexicographic order as a tie-break. Does not remediate already-written buckets (upload never deletes).

## Dev cycle: how work lands (CLI-0029)

Single-contributor repo, but every substantive change goes through a real PR. When asked to write an ADR (a `CLI-` record in `adr/`, numbered max+1), or to implement one already written, follow this without pausing for confirmation at each step — these steps *are* the standing authorization, per CLI-0029:

1. **Branch.** Once the ADR's content (or the implementation plan) is approved, `git checkout main && git pull && git checkout -b cli-XXXX-<slug>`. Reuse one branch for both writing the ADR and implementing it when a single request covers both. One branch in flight at a time.
2. **Build.** Commit the ADR file and/or implementation on that branch, using this repo's existing commit convention (`type(cli-XXXX): summary`; records through CLI-0160 landed as `adr-XXXX`, per CLI-0161 §1).
3. **Gate.** `mise run ci` must be clean before opening a PR.
4. **PR.** `gh pr create` — title matches the commit convention; body is a condensed ADR (short Context, condensed Decision bullets, a relative link to the full ADR file), never the full text.
5. **Changelog.** Once the PR exists, append one bullet in the same follow-up commit to `CHANGELOG.md`'s `[Unreleased]` section (top of file; create it if missing): `- CLI-XXXX: <one-line description> ([#N](PR URL))`. **No exemption for documentation-only PRs** — `release.sh` treats an empty `[Unreleased]` as a hard error (`has no bullets; nothing to release.`, exit 1), not a benign skip, so a PR that merges without a bullet turns the next release run red *and* leaves the published changelog silent about a change it shipped. Both happened to [#114](https://github.com/noisypigeon/pigeon-cli/pull/114).
6. **Merge.** `gh pr merge --squash --delete-branch` once CI is clean — no further confirmation needed.

7. **Release — automatic, nothing to do.** CLI-0117 made this a workflow: every push to `main` that is not itself a `chore(release): v` commit triggers `.github/workflows/release.yml` (a thin caller of the library's `rust-crate-release.yml` since CLI-0161), which bumps the patch version, retitles `[Unreleased]` to `[x.y.z] - date`, starts a fresh empty `[Unreleased]`, commits, tags, pushes, and *then* publishes to crates.io (push-before-publish per CLI-0150, with a sparse-index pre-check making a retry idempotent). So a merged PR ships on its own — do not hand-edit versions or cut a release, and expect the bot's `chore(release):` commit to land on `main` shortly after yours.

When an ADR's `## Out of scope` section has a genuinely-deferred item (not a permanent design boundary), file it via `mise run adr-issue` while landing that ADR — reuse an existing `out-of-scope`-labeled issue with `--issue N` if the same gap was already raised elsewhere. See CLI-0031.

## Commands

- `mise run build` — build the `pigeon` binary.
- `mise run pigeon -- <args>` — run the `pigeon` binary, e.g. `mise run pigeon -- keyring list`.
- `mise run test` — run the test suite.
- `mise run fmt` / `mise run fmt-check` — format / check formatting.
- `mise run lint` — clippy, warnings denied.
- `mise run ci` — fmt-check + lint + test, the full local gate.
- `mise run adr-issue -- <args>` — file (or reuse) a GitHub issue for an ADR's Out of scope bullet and link it back into the ADR; see CLI-0031. Runs the library's `adr-issue.sh`, with this repo's `area:*` labels in `.github/adr-issue-labels.txt`.
- `mise run release -- --dry-run` / `mise run build-release` — the library's `crate-release.sh` / `crate-build-release.sh`, as the release workflow runs them.
- `mise run observability-up` / `-down` / `-logs` — the library's local observability stack at `PIGEON_OBSERVABILITY_VERSION`.

## The library (CLI-0161)

This repo consumes three things from [`noisypigeon/library`](https://github.com/noisypigeon/library), each pinned:

- **Scripts**, at `/.lib-version` (a `workflows/vX.Y.Z` tag): `./fetch-lib.sh` (run by every task that needs it) clones the library into a gitignored `.lib-src/` at that ref. `.github/workflows/release.yml` is a thin caller of the library's `rust-crate-release.yml`, and its `uses:` ref **must equal `/.lib-version`** — bump both together.
- **The observability stack**, at `PIGEON_OBSERVABILITY_VERSION` in `.mise.toml`.
- **The `analyze-job-run` skill**, as the `pigeon-cli@library` Claude Code plugin, pinned by `ref` in `.claude/settings.json`. Changing the skill is a library PR plus a pin bump here.

To change any of them, land a library PR (it releases a new tag), then bump the pin here.
